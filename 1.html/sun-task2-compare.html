02

八个属性，各自管一件事

这张表里左边是我写的值，右边是删掉它会变成什么样。答辩时被问到某个数字，要能立刻说出它管的是哪一层。

键我写的值它控制什么
prev.translate ['-38%', 0, -220] 左邻片往左推自身宽度的 38%，并往屏幕深处退 220px；退得多，显得远
next.translate ['38%', 0, -90] 右邻片往右推 38%，只退 90px；退得少，显得近，像马上要顶上来
prev.rotate [0, 0, -9] 只转 Z 轴（平面内逆时针 9°），做出斜插进画面的角度
next.rotate [0, 0, 6] 顺时针 6°，和左侧反向；两边同号就会像整体歪掉
prev.scale / next.scale 0.82 / 1.06 小于 1 是退场，大于 1 是压过来；一个收一个放，才有纵深
opacity 0.6 / 0.65 邻片半透明，主片保持不透明；这一项负责"旧"和"新"的区分
limitProgress 2 允许同屏两张邻片参与动画，第三张起直接归位，避免远处一片乱影
shadowPerProgress true 阴影随进度连续变化，而不是到位才出现；拖动时不会突然闪一下
03

prev 和 next，到底在说谁

这是全篇最容易搞反的地方。名字是按位置取的，不是按"来"还是"去"取的。

prev · 左边那张 正在离场

往后缩、变暗、斜着退出去

它是当前这张左侧的那张。往后翻时，它被甩到左边去，所以缩小、加深、退到最远。往右翻回来时，它反过来变成进场者。

translate: ['-38%', 0, -220]
scale: 0.82 · rotate: -9° · opacity: 0.6
next · 右边那张 即将进场

放大、半透明、侧身等着上台

它是当前这张右侧的那张。往后翻时它往中间顶上来，所以 scale 大于 1、只退 90px、旋转反向，像从侧幕后面探出来。

translate: ['38%', 0, -90]
scale: 1.06 · rotate: 6° · opacity: 0.65
04

三个追问，写代码前必须想清

Q1prev / next 控制的是离场还是进场？
都不是，它们只认位置。prev = 当前幻灯片左边的那张，next = 右边的那张。 同一个对象在往后翻时是离场者，在往前翻时它就变成进场者——所以它既是离场也是进场，取决于你往哪个方向走。
Q2translate 里的百分号，相对谁算？
相对幻灯片自己的宽高，不是相对容器。'-38%' 是这张片子自身宽度的 38%。 所以窗口一变、slide 宽度一变，位移量会等比跟着变，布局不会错位。第三个数是 px，带不带引号都行，但别写成 '-220px'。
Q3rotate 写 '30deg' 行不行？位移改小会不会被盖住？
不行。rotate 必须是纯数字，单位是度，写成字符串不会报错但也不生效。位移改小（比如 -50% 改成 -20%）确实可能被当前这张压住，因为主片的层级更高； 解决办法是同时调 scale 和 translate 的 Z 轴，让邻片留在主片后面还有一段可见的边。
顺手纠正一个常见误解：网上有些文章会写 creativeEffect.setTransform，官方 CreativeEffectOptions 里没有这个键。 真正存在的是 prev、next、limitProgress、shadowPerProgress、progressMultiplier、perspective、transformEl 这七个。 自己写的时候如果照抄了不存在的键，页面不会报错，只是怎么调都没反应——这种"静默失效"最难查。
